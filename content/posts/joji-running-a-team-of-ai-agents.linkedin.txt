I run a team of AI agents on one 4-core server. The agents turned out to be the easy part.

Joji is my lead agent, built on the open-source Hermes framework. I message her on WhatsApp. Behind her: engineers that open PRs, a reviewer, a QA agent that tests on staging, an ops agent for my inbox, and an opportunity-hunt agent.

After 270+ logged changes, my conclusion: this isn't a collection of agents. It's an operating system for autonomous workers. The engineering that matters is around the agents:

→ Task state in files, one owner per transition, never in an agent's memory
→ One-shot runs with a written brief, so every hand-off is explicit
→ A deterministic driver (no LLM) moving PRs through review → fix → staging → QA → ship
→ Layered memory: capped shared rules, at most one lesson per run, searchable history
→ Permissions enforced by tools and caps, not prompts. Understanding an action never means permission to do it. Agents draft; I send.

Last 14 days: 855 agent runs, 96% finished cleanly. 223 PRs through the pipeline, 90% shipped, 64% with zero fix rounds. And 39% needed me at some point, which is the number I'm working on.

The write-up covers the architecture, the task lifecycle, the security model, three real incidents with root cause and fix, and what I still don't trust agents to do.
